型号见小米官方的 [G Pro 27U 2026](https://www.mi.com/shop/buy/detail?product_id=24141) 和 [G Pro 27U 原款](https://www.mi.com/redmi-monitors/g-pro-27u)。另有[社区设备记录](https://github.com/Evilom/AndroidDisplayVoiceBridge/blob/main/README.md#已验证状态)报告 27U 2026 使用相同 ADB 型号，但其验证的是局域网 ADB 与遥控器转文字。这里的候选判断不代表本项目已适配 USB 收音。

安装器仅按 ADB 型号 `MiTV_MFFU1` 筛选，不按商品名称判断。候选机型须先通过 `./mic.sh devices` 核对；型号不符时暂不支持。普通无 Android 系统、无可用 ADB 或无麦克风的显示器不在此方案范围。

## 本仓库整理版

`make check` 在上述 Mac / Python 3.9.6 通过：48 项测试、两个 Swift 程序构建、四个 shell 入口语法检查。这些软件测试使用合成音频和隔离目录，不采集人声、不启动真实登录任务。

- USB 选择排除网络设备，多台显示器要求明确选择；拒绝无效配置。
- WAV 解析保留首批样本并拒绝异常格式；非阻塞输出完整转发数据，堵塞约 8 秒后退出等待。
- 合成采音使用命名管道并清理，不生成录音文件。
- 隔离安装路径含空格，实际编译并临时签名；卸载保留日志和依赖，拒绝覆盖或删除归属不符的文件。
- 清理连接失败不会掩盖原始安装错误；ADB 路径失效可用新路径修复或卸载，失败时保留原配置。

- 旧服务停用，新服务启用登录自启动；实际重新登录尚未验证。

### 默认完整安装与分项安装

2026-11-03 将默认入口统一为桥接 + 守护，另提供 `--bridge-only` 与 `--guard-only`。

- 隔离测试验证默认顺序、分别安装、补齐缺失组件、重复执行保留绑定/增益，以及 `--no-start` 对两端生效。
- 失败测试验证新增组件回退、已有组件及配置原文保留；设备清理失败时保留连接记录。
- 首次 USB 授权等待有时限；损坏 APK 在写入安装文件前拒绝。实际 Swift 编译和隔离文件安装通过，Android 操作与服务启动在这些流程测试中模拟。
- 完整包包含可执行的双击入口、APK 与校验文件，排除私钥和本机配置；不要求普通用户安装 JDK / Android SDK。

新版安装器未在现用实例上重新安装或重启服务；此前守护的真机验证单独记录如下。首次在其他电脑上完成全部授权仍需验收。

### USB ADB 守护

2026-11-03 确认显示器 ADB 开关曾关闭；重新开启后，原 Mac 服务未重启即恢复收音。随后安装本项目的可选守护，旧网络守护继续停用。

- 守护 APK 在 JDK 17、SDK Platform 34 / Build Tools 35.0.0 构建、签名并安装；设备上的 APK 与本地产物一致。
- 守护启停、同签名更新、卸载及重新安装通过；采音配置和 ADB 当前状态保留，卸载移除本次添加的待机白名单。
- 主动关闭 `adb_enabled` 后约 3.6 秒自动恢复，USB 重新连通；随后 BlackHole 双声道输入实测正常，不保存录音。
- Wi-Fi 调试标志和 TCP 端口属性与安装前一致，未重新启用旧 AdbGuardian。
- 固件拒绝 shell 发送模拟开机广播；实际开机自恢复、长期待机及强杀后的表现仍未验证。实现与控制命令见[守护说明](guardian.md)。

2026-11-04 使用者反馈，USB 收音与守护组合在约一天的日常使用中保持稳定；这是使用者观察，不替代下列专项验收。

## 待设备验收

- 权限提示和登录后后台运行；macOS 13 最低版本及 Intel Mac 的实际运行。
- USB 拔插、显示器与 Mac 待机/唤醒和重启后的恢复。
- HDMI 模式下 USB 是否保持、两台电脑之间的 USB 切换；其他型号与固件。
- 长时间稳定性、延迟、音质、回声，以及各语音应用兼容性。
- **微信通话尚未通过**：原机曾出现菜单与底层设备不一致、对方听不到声音，仍需通话中定位。

GitHub CI 的软件检查结果见[Actions](https://github.com/zetttt/mimonitor-mic/actions)。准备好设备后，先通过 `./mic.sh doctor`，再用目标应用确认文字或对方听感，随后逐项验证拔插、唤醒和重启。反馈请附版本、复现步骤和脱敏错误。
